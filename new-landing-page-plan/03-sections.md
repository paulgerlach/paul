# Phase 3: Sections (static)

The implementations live in `$lib/landing/sections/region/`, because the Germany page (phase 8) uses the same 13 sections. Each page then has a wrapper per section in its own folder: `pages/messdienstanbieter-city/sections/` (this phase) and `pages/messdienstanbieter/sections/` (phase 8). Each implementation takes the `content: RegionContent` it needs (or a slice of it) as a prop and has its CSS ported from the design into a scoped `<style>`. `+page.svelte` only composes them in order. As on `/messdienstwechsel`, this phase produces the **final static markup**: every animated element is already in its end state, and phase 4 adds the motion.

`city` below means the content module (`RegionContent`); the examples are Berlin's copy. Every heading, intro and bullet comes from it (phase 2.4), even where the table quotes Berlin's text.

## Accessibility in this phase

- Heading order H1 → H2 per section → H3. The `Duo` and `Trio` cards have H3s without a section H2: the sections keep the design's `aria-label` ("Heidi für Mieter und Verwaltung", "Heidi im Überblick"), and a visually hidden H2 is added so the outline has no gaps.
- Decorative mock-ups are `aria-hidden` when the text next to them says the same. The interactive ones (map, billing buttons, phone tabs, portfolio tabs, trio buttons) stay accessible and are labelled.
- No `href="#"` or links to `claude.ai/artifact/…` are shipped. "Anmelden" in the design is the site's "Einloggen" (`LOGIN_URL`).
